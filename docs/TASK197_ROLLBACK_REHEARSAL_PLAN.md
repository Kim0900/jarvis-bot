## 2. 실행기 (`task197_safe_runner.py`) — 4차 정정(#5673) 반영
```
PGDSN='<운영 DSN: 환경변수로만>' python3 tests/sql/task197_safe_runner.py --approval-file <마기 서명 승인 파일> [--report run.json]
```
**운영 모드가 받는 인자는 이것뿐이다.** 한도(3000/250/2000 ms, 워치독 8 s, 모드 begin)와 파일 경로는 코드에 고정이며 어떤 플래그로도 바뀌지 않는다. 시험용 인자(`--sql --expect --snapshot --sha256 --statement-timeout-ms --lock-timeout-ms --idle-tx-timeout-ms --watchdog-s --mode --test-child-fault --test-hold-lock-s`)는 운영 모드에서 **연결 전에 거부**된다.
구조: **감독자**(이 프로세스) = 검증·관찰자 세션·잠금·스냅샷·보고서 / **관찰자 세션** = `pg_try_advisory_lock` 보유 + 읽기 전용 스냅샷 / **자식 프로세스** = 전용 연결 하나로 `BEGIN; SET LOCAL …; 유효값 확인; DO; ROLLBACK`.
순서: ① (연결 전) 시험 인자 거부 → 서명 승인 검증(아래 8-A) → 해시 대조·린트 → ② 관찰자 연결(`lock_timeout 1 s`, `statement_timeout 5 s`) → ③ **단일 실행 잠금 획득**(실패 시 아무것도 시작하지 않고 종료) → ④ 승인 id 사용 처리 → ⑤ 기존 `task197_rehearsal` 세션 확인 → ⑥ 사전 스냅샷 → ⑦ 자식 시작(감독자 마감 = 워치독 8 s + 2 s + 3 s = 13 s, 초과 시 SIGKILL) → ⑧ 자식 보고 수신 → ⑨ 관찰자가 세션 소멸 확인·사후 스냅샷·불변식 대조(스냅샷이 잠금에 막히면 "잔여물 증명 불가 — HOLD"로 보고하고 카탈로그 뷰로 확인 가능한 값만 기록) → ⑩ 잠금 해제 → 엄격 판정. 재시도 없음. `--post-check-only`는 감독자 자체가 죽었을 때 쓰는 읽기 전용 점검이다.

**4-1 잠금 상한 100/250/500 ms (DO 상한을 바꾼 변형 산출물)**
| 상한 | 유휴 테이블 20회 | 바쁜 테이블(보유자가 쓰기급 잠금을 *보유자 시작 기준* N ms 유지; 실행기 기동 약 0.2 s가 앞섬) | 3클라이언트 동시 |
|---|---|---|---|
| 100 | PASS 20/20, p95 112, max 112 ms | 60·200: PASS / 400·800: 55P03 (≈115 ms에 포기) | 15회 중 PASS 9·동시 세션 거부 6 |
| **250** | PASS 20/20, p95 90, max 90 ms | 60·200·400: PASS(400은 ≈262 ms 대기) / 800: 55P03(≈265 ms) | PASS 10·거부 5 |
| 500 | PASS 20/20, p95 109, max 109 ms | 60·200·400: PASS / 800: 55P03(≈515 ms) | PASS 9·거부 6 |
- 모든 55P03은 깔끔한 종료(센티널 `FATAL=55P03`, 종료코드 2, 잔여 0). 동시 실행은 **실행기가 거부**(이미 `task197_rehearsal` 세션 있음) — 의도된 동작, 경합 실패가 아님. 거부 전에 DDL·쓰기 없음.
- 선택: **250 ms**. 읽기 지연 최악이 deadlock_timeout(1 s)보다 훨씬 작고, 측정된 짧은 쓰기 보유(≤ 약 0.2 s)는 견딘다. 100 ms는 전형적인 짧은 보유에도 너무 일찍 포기하고, 500 ms는 얻는 것이 400~800 ms 구간뿐인데 대기열에 선 읽기 지연이 두 배가 된다.

**4-2 문장 한도 2/3/5 s**
| 한도 | 정상 20회 p95/max (ms) | 쓰기+체크포인트 부하(3 스레드) 20회 p95/max | 7초 정지 주입 5회: 끝난 시각 / 바깥에서 본 ACCESS EXCLUSIVE 보유 |
|---|---|---|---|
| 2 s | 103/103 | 196/196 | 2001 ms / 약 1970 ms |
| **3 s** | 132/132 | 206/206 | 3001 ms / 약 2975 ms |
| 5 s | 103/103 | 144/144 | 5001 ms / 약 4967 ms |
- 모두 정지 주입은 `57014` 취소 후 롤백, 잔여 0, 종료코드 2.
- 선택: **3 s**. 정상은 최대 약 0.2 s(15배 여유), 장애 시 잠금 보유 상한이 약 3 s. 2 s도 정상 구간엔 충분하나 운영은 DB 크기·디스크 지연이 미측정이라 여유를 택함. 5 s는 장애 시 쓰기 차단이 5 s까지 감.
- 느린 I/O: 실제 디스크 지연은 만들지 못했다. 대체로 다른 DB에서 3개 스레드가 쓰기+체크포인트를 반복하는 부하로 측정(위 표). 이는 대용량 운영 I/O의 대체물이 아니다.
- 연결 상실 거동(실행기 시험 R8~R13): 문장 한도 1 s는 바깥에서 잠금 약 0.96 s 후 해제. 클라이언트 SIGKILL(한도 3 s): 약 2.96 s에 해제, 세션 소멸. 클라이언트 SIGSTOP 블랙홀(한도 2 s): 약 1.97 s에 해제(**문장 오류가 잠금을 풀어준다 — 명시적 트랜잭션이어도 abort 시점에 해제, ROLLBACK을 기다리지 않음**), 남은 유휴 세션은 `idle_in_transaction_session_timeout`이 정리(해제하지 않으면 세션이 남음: R12 대조군에서 확인).
- 로컬 WAL: 1회 약 167~173 KB, 이벤트 시퀀스 소모 44. 운영은 재생 이력이 커서 약 0.5 MB 추정(미측정).

## 9. 5차 정정 — 카산드라 #5719 C197-CHILD-BYPASS / 마기 #5722 (P0-FIX-197-01)
**결함(정적 확인, 운영 악용 없음)**: 4차 실행기에는 `--child <cfg>` 인자가 있어, 서명 승인·매니페스트·SQL 해시 검증 *전에* 임의 설정 파일의 SQL을 실행하는 경로가 있었다. "신뢰 기준점 None이면 운영 실행 전부 거부"는 부모 경로에만 해당했다. 이번 정정으로 그 경로가 **존재하지 않는다**.

### 9-A. 구조
- `--child`는 삭제되었다(알 수 없는 인자 → argparse가 연결 전 거부). 자식은 명령줄 모드가 아니라 감독자가 `python -I -c "…child_entry(<fd>)"`로 띄운다.
- 감독자는 **봉인 권한(capability)** 하나를 상속 파이프로만 넘긴다: 서명 승인 원문, 고정 매니페스트, 난수 nonce. 자식은 argv·파일 경로·DSN·한도를 받지 않는다.
- 자식은 연결 **전에** 독립적으로 확인한다: ① MAGI 서명 승인(신뢰 기준점, Ed25519, 정확한 git 커밋, 가드 파일 6개 해시, 고정 매니페스트, 30분 이하 시간창, HOLD 해제·업로드 없는 시간대) ② 실행할 DO 텍스트를 직접 읽어 해시가 승인된 값·expect 값과 같고 구조 검사(lint)를 통과 ③ 감독자가 이 승인을 이미 승인·소비했고(사용 기록) 자식 자신의 1회용 토큰을 아직 쓰지 않았음 ④ (연결 후, DO 전) 감독자 관찰자 세션이 admission advisory lock을 쥐고 있음.
- 자식 보고는 nonce와 권한 문서 digest를 되돌려 주고, 감독자가 일치하지 않으면 보고를 버린다(봉인 확인). 감독자가 죽으면 자식은 0.2초 주기 감시로 즉시 취소·종료한다.

### 9-C. 필수 시험 대응 (마기 #5722)
직접 `--child`+가짜 cfg → E1 · 서명 없음/만료/위조 → A3~A8, E4a~E4c, E4i · SQL 변조 → A17~A19, E4j~E4k, E4q~E4r · 한도 변조 → A12~A13, E4d~E4e, E4o · `--test-mode` 우회 → B3~B5, E4l~E4n · 부모 크래시 → E13, C4 · 정상 서명 경로 → A1, E12. 거부 시험은 가짜 DB(연결 횟수 계수 리스너)에서 **연결 0회**를 확인하고, 실제 일회용 DB에서는 카탈로그·데이터 불변을 확인한다.

### 9-D. 남은 한계 (숨기지 않음)
- 실행기 자체를 고친 운영자는 이 검사를 건너뛸 수 있다 — 대응은 절차(서명이 정확한 커밋·파일 해시를 묶음, 실행 전 체크아웃 재해시, 자격은 승인과 함께만 전달). 운영자가 임의 파이썬을 실행할 수 있으면 어떤 코드 검사도 우회 가능하다.
- 서명 키 보관자와 신뢰 기준점 설정(MAGI 결정)이 없으므로 이 저장소 상태에서 운영 실행은 여전히 불가능하다(`TRUST_ANCHOR_PUBKEY_SHA256 = None`).
- 운영 PG17.6·실제 규모는 미검증. 운영 실행·병합·배포 없음, #5486 HOLD 유지.
