- Telegram 발송은 현재 send_telegram_broadcast(ALLOWED_CHAT_ID, ALLOWED_CHAT_ID2)로 오류를 삼키고 message_id를 반환하지 않음 → 신규 검증형 발송 함수 필요(F2).

## 1. 보장 범위(과장 금지)
- G1 판독이 확실할 때만(2xx + 유효 JSON 리스트) 경보 발행. **감지 입력 읽기(scheduler_status·tasks·events·call_image_ingestions)도 같은 기준**: 실패 시 해당 점검 블록은 "점검 자체 실패"로 처리하고 그 블록의 알림·해소 판정은 하지 않는다(과거: sb_select가 실패를 []로 바꿔 필수 job 13건이 'missing'으로 오경보될 수 있었음. 무필터 조회도 db-max-rows 상한에서 같은 오판 가능).
- G2 같은 키에서 확보 CAS에 이긴 쪽만 PATROL_ALERT 삽입, 삽입 결과 불명 시 **재삽입 금지(UNKNOWN)**. 이벤트 행은 키·확보당 ≤1(늦은 커밋이 있어도 재시도로 늘리지 않음). 이벤트 행 미전달 가능을 수용. 인스턴스 간 정확히 한 번은 주장하지 않음(DB 고유 제약 없음).
- G3 Telegram: **확보 1회당 모호한 결과는 재전송하지 않음**; 확정 미전송 실패만 최대 2회 시도. 모호했던 경보는 조건이 지속되면 **일반 쿨다운 만료 후 새 확보로 다시 전송될 수 있음**(그 시점의 중복 가능성 수용). 정확히 한 번·무손실 주장 안 함. 분류표(PTB 20.7/httpx, 구현 시 설치 버전으로 재확인): 확정 미전송 = `err.__cause__`가 ConnectError·ConnectTimeout·PoolTimeout, 또는 BadRequest·Forbidden·InvalidToken·ChatMigrated·RetryAfter(서버가 거절); 모호 = ReadTimeout·WriteTimeout·WriteError·ReadError·RemoteProtocolError·HTTP 5xx·그 외 분류 불가 전부(기본값=모호). `TimedOut`/`NetworkError`는 원인 검사 없이는 판정하지 않는다.
- G4 서버 다운·프로세스 사망 감시는 B단계(별도 승인). 로컬 상태는 재시작 시 소멸.

## 2. 1차 상세
### S1 읽기(fail-closed)
- 읽기 대상 정리: ① 필수 job 점검은 `scheduler_status?job_name=in.(필수 job 목록)` 필터 조회(무필터 전체 조회는 patrol_alert::* 누적과 db-max-rows 상한으로 'missing' 오판 가능 → 폐기); ② 쿨다운 장부는 `job_name=like.patrol_%::*`(patrol_alert::* 와 patrol_meta::* 모두)를 `sb_get_all_strict`(페이징 검증)로 1회/실행 일괄 조회; 키 부재는 '목록에 없음'일 때만 신규 확보(POST ignore-duplicates)이며 POST가 0행이면 패배가 아니라 '다른 실행이 먼저 생성'으로 보고 이번 실행은 발송 없이 다음 실행에서 재판독; ③ `get_kakao_daily_completeness_v1` RPC도 엄격 판독(실패는 '정상'이 아니라 점검 실패, 해소 판정 금지).
쿨다운 장부와 감지 입력은 `sb_get_strict`. 불명 시 이벤트 삽입 금지. 불명/장부 불가 알림은 프로세스 로컬 **전역 단일 메타 키 `patrol_meta::ledger_unreadable`**로 Telegram 직접 1건(DB 비경유, 로컬 쿨다운 30분, 순라 1회 실행당 최대 1건; 크래시 루프·인스턴스 수만큼 곱해지는 상한은 잔여 위험으로 공개).
### S2 장부 값 형식과 호환(배포 혼재 대응)
- 키 이름은 기존 `patrol_alert::<key>` 유지(새 네임스페이스 없음). 단 정규화로 이름이 바뀌는 키는 기존 행과 이어지지 않아 **배포 직후 1회 재경보**가 생김(리플레이로 대상 키 수를 구현 전 산출·보고, 상한 = 개명 키 수). 기존 평문 값(`[CRITICAL] …`)은 **legacy**: 쿨다운 나이는 last_run_at 기준, 접두 `S2|`가 없으면 legacy로 읽고 상태 1(최초)부터 시작.
- 새 값: `S2|<STATE>|c=<claim_epoch>|ra=<retry_after_epoch 또는 빈칸>|t=<token>|e=<event_id>|a=<TG 시도수>|r=<복구 시도수>|tg=<수신자해시:{ok,fail,amb}를 쉼표로 나열>|h=<알림 앞 300자>`. **h는 항상 마지막 필드**, 저장 시 `|`를 `/`로 치환, 파싱은 `split('|', 9)`(maxsplit)로 h 안의 구분자 영향 차단, 전체 900자 이내(헤더 ≈200 + h 300 + tg). `S2|` 접두인데 파싱 불가 → 상태 불명(fail-closed + 메타).
- **쿨다운 시계는 `c=`(최초 확보 시각)**, 전이마다 last_run_at은 새 값으로 갱신(CAS 조건 용도)하되 쿨다운 계산에는 쓰지 않음(legacy 값만 last_run_at 사용). 구버전 코드가 겹쳐 실행되며 blind upsert로 덮어쓰면 legacy 평문이 되어 그 시각부터 last_run_at 기준으로 쿨다운이 이어진다(상호 호환, 구버전은 last_run_at만 읽음).
- "단조 증가/ABA 없음" 주장은 철회: 정합성은 **동등 비교 CAS**로만 보장(시계 오차는 쿨다운·유예·ra 만료 시점을 어긋나게 하며, 이로 인한 조기 복구는 §6에 공개한 이벤트 중복 위험이 됨. 이중 승리 자체는 CAS가 막음).
### S3 확보(claim)와 모든 전이는 last_run_at CAS
- 모든 상태 전이(확보·EVENT·TG_SENDING·결과·UNKNOWN 전이)는 `PATCH ?job_name=eq.<key>&last_run_at=eq.<직전에 읽은 원문 값>`(NULL이면 `is.null`)로 하며 **항상 새 last_run_at을 씀**(그래야 늦은 두 번째 경쟁자가 패함). 값은 읽은 원문 문자열 그대로, httpx `params=`로 인코딩. 신규 키는 POST on_conflict=job_name + ignore-duplicates. 신규 `sb_write_strict`가 승/패/AMBIGUOUS 분류.
- AMBIGUOUS 확보: 삽입하지 않고 로컬 쿨다운 기록 + 메타(UNKNOWN 경로).
### S4 삽입·UNKNOWN·복구
- 승자는 PATROL_ALERT 삽입(detail에 토큰) → 성공 시 CAS로 `EVENT`(e=event_id). 삽입 불명/타임아웃 → 재삽입 금지, 상태 `UNKNOWN`(ra=지금+15분)으로 CAS 전이 + Telegram 메타 1건(알림 앞 300자 포함 — 내용 없는 통지 방지).
- **복구 규칙(유예 10분 초과 상태를 만난 실행이 last_run_at CAS로 1명만 전이)**: `CLAIMED`(삽입 전 중단) → UNKNOWN. `EVENT`(삽입 후 TG 시작 전 중단) → event_id로 strict GET해 알림 본문 확보 후 `TG_SENDING`으로 CAS해 발송(Telegram이 시작되지 않았으므로 중복 아님); 본문 조회 불명이면 이번 실행은 보류하되 **복구 시도수 r을 CAS로 +1**(별도 카운터, TG 시도수 a와 분리), r≥3이면 UNKNOWN. **모든 비종결 상태는 c 기준 일반 쿨다운 만료 시 새 확보 자격을 가짐**(영구 억제·livelock 없음). 이벤트 없음(0행)이면 UNKNOWN. `TG_SENDING`(발송 후 ACK 기록 전 중단) → `TG_UNCONFIRMED`(확보 내 재전송 안 함, G3; ra 없음 — 일반 쿨다운 만료로만 재경보).
- 복구 전이로 UNKNOWN이 되는 모든 경우(CLAIMED·EVENT 0행·r≥3·삽입 불명)는 ra=지금+15분을 설정하고 메타 1건을 보낸다. 메타 규칙 통일: 알림 단위 메타(UNKNOWN 통지, 본문 300자 포함)는 해당 경보의 장부 CAS에 묶여 경보당 1건(8건 상한에 포함); 장부 판독 불가 메타(`patrol_meta::ledger_unreadable`)와 루프 오류(`patrol_meta::loop_error`)만 전역 키·로컬 쿨다운 30분·실행당 1건.
- 재경보 자격: 일반 쿨다운 만료(c 기준) **또는** 상태 UNKNOWN이고 now≥ra(+15분; 이벤트 행만 불확실한 경우) → 새 확보. TG_UNCONFIRMED·TG_PARTIAL의 모호 수신자는 ra를 두지 않고 일반 쿨다운만 적용. 이때 원래 삽입이 늦게 커밋됐다면 같은 조건의 이벤트 행이 2개까지 생길 수 있음을 수용(UNKNOWN 1회당 +1).
### S5 Telegram(검증형)
- 신규 `send_telegram_checked(text)`: 수신자별(기존 ALLOWED_CHAT_ID, ALLOWED_CHAT_ID2의 비어있지 않은 값) 결과 {definite_ok(message_id), definite_fail, ambiguous}를 반환. 상태에는 수신자 해시별 결과를 기록(`tg=<hash>:{ok,fail,amb} 쉼표 나열`).
- 순서: 전송 직전 `TG_SENDING`으로 CAS(실패 시 전송하지 않음) → 전송 → 결과를 CAS로 `TG_ACKED`(전부 ok) 또는 `TG_PARTIAL`(definite_fail 없음: 일부 ok+일부 amb) 또는 `TG_FAILED`(definite_fail이 하나라도 있고 a<2: a+1 — 증가 전에 a<2를 검사, 재시도 TG_SENDING 전이에서는 a를 올리지 않음; TG_FAILED 재시도는 유예를 기다리지 않고 다음 실행에서 가능). TG_FAILED는 복구 대상 상태로 취급: 다음 실행이 같은 키의 조건이 **여전히 감지될 때만**(상태 없는 감지기) last_run_at CAS로 `TG_SENDING`(a+1) 전이 후 재시도하며 새 확보·새 이벤트 행은 만들지 않음. 본문은 이벤트 행 e=를 strict GET해 얻고 조회 불명이면 r+1 규칙. 재시도도 8건/120초 상한에 포함. 조건이 사라졌으면 `TG_GIVEUP`. 재시도 대상은 **definite_fail 수신자만**, a<2, 다음 실행에서; ambiguous 수신자는 재전송 안 함. **경보당 1메시지(묶음 폐기)**: 실행당 처리 상한 8건·전체 마감 120초(신규 확보 시작 금지 시각), 초과분은 상태 없는 감지기가 다음 실행에서 재감지. 호출당 타임아웃 10초 유지. 복구 유예는 **해당 상태 진입 시각(마지막으로 쓴 last_run_at)** 기준 10분이며, 최악 단일 경보 처리(쓰기 5 + 재조회·이벤트 GET + Telegram 2회 ≈ 90초)+마감 120초보다 충분히 크므로 진행 중 행을 다른 인스턴스가 복구하지 않음(시계 오차가 크면 예외 — 잔여 위험). 경보당 쓰기 5회(확보·삽입·EVENT·TG_SENDING·결과) + 실행당 읽기 1회.
- **CAS 종결 규칙**: 삽입 성공 후 EVENT CAS 패배 → 상태 소유자가 따로 있으므로 이번 실행은 Telegram 발송하지 않고 로그만. TG_SENDING CAS가 AMBIGUOUS → 발송 전에 strict 재조회 1회: 행이 내 토큰의 TG_SENDING이면 소유로 보고 발송, 여전히 EVENT(내 last_run_at)이면 CAS 1회 재시도, 그 외·불명이면 발송 안 함(경보 미발송 가능 — 잔여 위험). 결과 기록: 전부 ok→`TG_ACKED`; 일부/전부 definite_fail이고 a<2→`TG_FAILED`(다음 실행에서 definite_fail 수신자만 재시도, a+1); a≥2 또는 남은 수신자가 모호뿐→`TG_GIVEUP`(종결, 일반 쿨다운 만료까지 유지); 일부 ok+일부 모호(definite_fail 없음)→`TG_PARTIAL`(종결); **definite_fail이 하나라도 있고 a<2이면 ok 여부와 무관하게 `TG_FAILED`**(ok 수신자는 tg= 에 보존되어 재시도 대상 아님). 종결 상태: TG_ACKED, TG_GIVEUP, TG_PARTIAL, TG_UNCONFIRMED.
- 순라 자체 오류 직접 전송(루프 예외 경로)도 고정 키 `patrol_meta::loop_error`의 같은 확보를 사용(장부 판독 불가일 때만 S1의 로컬 쿨다운 30분으로 대체; 정상 시 DB 확보 규칙 적용 — 메타 규칙 통일 항목의 '전역 키·로컬 쿨다운'은 장부 판독 불가 메타에만 해당). EVENT CAS 결과가 AMBIGUOUS이면 발송하지 않고 유예 후 복구 규칙에 맡김.
### S6 키·쿨다운·라우팅
- 키=(원인군, 대상, 정규화 서명), 가변값(시각·경과시간·문장 전문·kakao_completeness의 건수 숫자) 제외, 예외 문구가 비면 예외 클래스명을 서명에 사용. 묶음키 없음(#204 후 점검 자체 실패 7종은 개별 키).
- 쿨다운: 점검 자체 실패 2h, 스케줄러 FAIL·stale job별 최초 즉시 + 6h(4종 최초 FAIL 보존), ingestion source별 24h, 24h 미복구 에스컬레이션 표기. 최악 동시 폭주 상한 = 활성 키 종류 수.
- 해소: 해당 점검 블록이 이번 실행에서 정상 완료(읽기 포함)한 경우에만 해소 처리.
### S7 순서 의존

## 3. 2차 개요(상세는 1차 PASS 후 별도)
장기점유 P0 6h/P1 24h·발송 직전 task 상태 재조회, 일일 요약(TG_UNCONFIRMED/UNKNOWN 건 포함·읽기 실패 시 "집계 불가"), 작업지시 발행 알림(event_type 정확 일치+actor 허용목록, 정보성, 새니타이즈 300자), #194 PARTIAL 가시화, 대상표 운영/제외 분리, 미등록 job 일 1회 정보 경보. 외부 데드맨·outbox 일반화·에이전트 자동 기동은 범위 밖.

## 4. 리플레이(읽기 전용, SQL 1문, (created_at,event_id) 순 키별 슬라이딩 쿨다운)
입력 579건(10/10 00:00~10/14 10:30 KST), #163 대상·퇴역 게이트 60건 제외 → 519건. 1차 규칙(점검 자체 실패 7키 2h, FAIL/stale 6h, ingestion 24h): FAIL 80→16(4×4), stale 12→2, 점검 자체 실패 →28(7키×4폭주), ingestion 7, 참고(2차 범위) 장기점유 6h 가정 49. FAIL 80→16·stale 12→2는 이룸 5105 시뮬과 일치(독립 구현 교차). 4종 최초 FAIL 보존은 구현 시험에서 재현.

## 5. 시험(구현 단계)
sb_write_strict(승 1행/패 0행/2xx 전부/빈·깨진·비2xx·전송오류=AMBIGUOUS); last_run_at NULL·'+'·마이크로초 왕복·원문 값 재사용; 기존 last_result에 쉼표·따옴표·900자 값 덮어쓰기와 legacy↔S2 상호 읽기(구버전 blind upsert 혼재); 동시 CAS(1승1패)와 전이마다 새 last_run_at(늦은 경쟁자 패); 복구 규칙 4종(CLAIMED/EVENT/TG_SENDING 유예 초과, 본문 조회 불명); UNKNOWN 재삽입 0·메타 1(본문 포함)·ra 후 재경보 자격; 삽입 타임아웃·지연 커밋 재생; Telegram 수신자별 결과(부분 성공 재시도는 definite_fail만, ambiguous 재전송 0, 시도 ≤2); 감지 입력 읽기 실패 시 필수 job 'missing' 오경보 0건; 메타 경보 단일 키·실행당 ≤1; 라우팅(취소 task→#160); 해소 판정; 리플레이 재현. 뮤테이션: CAS→blind write, 재삽입 허용, 불명 시 발행, 전이 시 last_run_at 미갱신, 감지 읽기 lenient 복원, ambiguous 재전송 허용 각각 시험 실패.

## 6. 잔여 위험(공개)
배포 겹침 시 구버전 코드는 scheduler FAIL·stale에 1h 쿨다운을 쓰고 blind upsert가 c=를 지우므로 겹침 동안 시간당 재경보가 생기고 신버전 6h 시계는 그 시점부터 재시작(겹침 시간으로 한정). 시계 오차: ra·유예는 시각 기반이라 오차가 큰 인스턴스가 다른 인스턴스 진행 중 행을 일찍 복구해 이벤트 행이 늘 수 있음(CAS로 전이는 1명만). TG_SENDING CAS 모호 후 재조회가 불명이면, 또는 EVENT CAS가 구버전 blind upsert에 패하면 이벤트 행은 있으나 Telegram 미발송 가능. 이벤트 행 미전달 가능(UNKNOWN), 이벤트 행 2개까지 가능(UNKNOWN 재경보 시), Telegram 크래시 손실(TG_UNCONFIRMED)과 부분 중복 없음·손실 가능, 서로 다른 키의 동시 지연 커밋은 키 종류 수까지, 로컬 메타 쿨다운은 재시작 초기화·인스턴스 수 곱, 서버 다운 B단계, 구버전 혼재 시 blind upsert로 상태 소실(쿨다운은 last_run_at 폴백으로 유지), 폭주 반복 트리거 원인 미확정, ALLOWED_CHAT_ID2 실제 설정값은 코드/환경 확인 필요(구현 단계에서 확인).
