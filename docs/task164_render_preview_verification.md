# Task #164: PC 없이 Render PR 미리보기에서 검증

## 범위

기존 `jarvis-ocr-tesseract` Render 서비스의 PR 미리보기만 사용한다. 운영 main/서비스는 변경하지 않는다. 미리보기는 서비스의 환경변수(기존 OCR.space 키)를 처음 생성할 때 복사한다. 이미지 자체는 GitHub에 추가하지 않는다.

1. Render 서비스의 Previews에서 Pull Request Previews를 `Manual`로 활성화한다. PR #25에 `render-preview` 라벨을 붙이면 격리된 미리보기가 생성된다. 2026-09-29에 이 설정과 생성·배포를 확인했다.
2. 미리보기 로그의 `[TASK164_PREVIEW_ACCESS]` 토큰으로 전용 URL을 만든다. 이 토큰은 사용자에게만 전달하고 공개 PR에 게시하지 않는다.
3. Android의 브라우저에서 전용 URL을 열어 9/28 Golden **원본 JPEG**를 업로드한다. 서버는 SHA-256이 정확히 일치하는 1개 이미지만 받아들이며 실행도 한 번만 허용한다. 복사본을 서버 디스크에 잠깐 보관한 후 즉시 삭제한다.
4. 결과 링크는 자동 갱신된다. 주소 등 민감정보가 표시될 수 있으므로 공개하지 않는다. `ok`, `status`, 헤더 10건/70,400원, 직접결제 라벨 1건, 실제 호출 수, 각 OCR 지연, 카드별 시각·주소·요금을 원본과 대조한다.
5. 판정이 끝나면 PR의 `render-preview` 라벨을 제거해 미리보기를 없앤다. Render 서비스 미리보기는 기본 서비스 설정을 복사하므로 작업 중 새 DB 접근이나 운영 쓰기 경로를 호출하지 않는다.

## 제한

- 미리보기 기능 활성화는 Render 커넥터가 제공하지 않는다. Dashboard에서 설정했고 현재 `Manual`이다.
- 미리보기는 운영 서비스와 독립된 인스턴스이나 같은 환경변수를 복사한다. 시작 전에 `IS_PULL_REQUEST=true`와 OCR 키 설정 여부를 확인한다. 전용 폼은 이 값이 true일 때만 등록된다.
- 무료 OCR API 한도와 Render 미리보기 이용량은 실제 사용에 따라 차감될 수 있다. 검증 폼은 배포 인스턴스마다 Golden 원본 한 번만 실행한다.
- 이 검증은 카드 파서 정확도 판단 자료다. 운영 배포/병합 및 DB 저장은 포함하지 않는다.

## 2026-09-29 실측 결과

- 최초 Golden 실행은 `LAYOUT_NO_TIME_ANCHORS`로 안전 중단됐다. 헤더 10건·70,400원은 읽었으나 OCR.space가 `22 : 32 - 22 : 40`처럼 콜론 양쪽에 공백을 반환한 것을 시간 정규식이 놓쳤다. 이때 2회 호출, 카드 0건이었다.
- 공백을 허용하고 시각 범위를 검사하도록 파서를 수정한 다음 격리된 미리보기를 재배포했다. 동일 원본 재검증에서 `COMPLETE_LAYOUT_VALIDATED`: 10개 카드, 합계 70,400원, 직접결제 표시 1건, 재OCR 0회, OCR.space 기본 2회. API 보고 처리시간은 624ms와 624ms였다.
- 직접결제 1건은 사전 수동 Golden 대조값이다. 운영 화면 헤더에서는 독립적으로 알 수 없다. 결과 한 장만으로 운영 전환을 승인하지 않는다. 읽기 전용 shadow 비교와 재OCR 한계·지연 측정이 다음 관문이다.
