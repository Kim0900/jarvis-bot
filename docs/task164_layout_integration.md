# Task #164: daily_history 카드 파서 전환 계획

## 검증값의 출처

- 표시건수·표시금액은 같은 이미지의 첫 운행 시간행 위에 있는 OCR 좌표 헤더에서 추출한다. 후보가 없거나 둘 이상이 충돌하면 중단한다. CLI의 `--expected-count`와 `--expected-sum`은 Golden 수동 대조용 선택 옵션이며 운영 입력값이 아니다.
- 직접결제 건수는 화면 헤더에 없으므로 독립적인 사전 검증값으로 사용하지 않는다. 각 카드의 `직접결제` 라벨을 추출해 관측 건수로 보고한다. 라벨 누락에 따른 자동결제 오분류 가능성이 남는다. Golden 검증에서만 이미지 육안 판독값을 `--expected-direct-count`로 넣고 대조한다.
- 운영 저장의 최종 진실 기준은 헤더 건수/합계, 시간 앵커 수, 카드별 필수 필드와 요금합이다. 결제수단은 Golden 및 다양한 신규 샘플의 직접결제 라벨 재현성을 확인하기 전까지 별도 위험 항목으로 둔다. 날짜 NULL 및 DB 원자 저장 조건도 기존 검증 경로 그대로 유지해야 한다. **현재 Overlay PoC 출력에는 운행 날짜 추출이 없다.** 통합 PR에서 화면 헤더 날짜를 OCR로 추출·검증하고 기존 날짜 관문에 연결하기 전에는 저장 경로에 사용할 수 없다.

## 기존 파이프라인과의 관계

현재 PR은 읽기 전용 PoC다. `daily_history_parser.py`와 `bot_v5_legacy.py`의 운영 파서, Render 저장 경로, main은 변경하지 않는다.

1. Golden 실이미지에서 OCR.space Overlay 좌표·헤더·15건 상한·요금·주소·결제라벨을 검증한다. 여기서 실패하면 저장 없이 원인을 기록하고 알고리즘을 수정한다.
2. 별도 통합 PR에서 현재 `daily_history` 경로 옆에 카드 파서를 shadow로 실행한다. shadow는 DB/Drive를 수정하지 않고 두 파서의 카드별 시각·주소·요금·결제방식과 호출 수·지연을 비교한다. 운영 저장은 기존 경로만 수행한다.
3. 다수의 신규 샘플에서 일치하고 시간·호출량 기준을 충족하면 별도 승인으로 카드 파서를 primary로 전환한다. 이전 텍스트 파서는 자체 날짜/헤더/앵커/합계 검증에 독립적으로 합격할 때만 폴백 후보가 된다. 두 파서 결과가 충돌하면 어느 쪽도 추측해 저장하지 않는다.
4. 실제 저장 전에는 source_id 멱등성, 날짜, 건수, 합계, 카드 필수 필드를 다시 검증하고 일괄 원자 저장한다. 성공 응답 뒤에만 Drive 파일을 이동한다. 폴백 제거 여부는 운영 관측 후 별도 결정한다.

## Task #93 및 호출 예산

Task #93은 9월 16일 이후 OCR.space 우선·Tesseract 폴백을 운영 선택으로 기록한다. 따라서 쟁점은 외부 OCR 도입 여부보다 호출량·지연·장애 시 동작이다.

- 현재 PoC는 기본 2회(긴 이미지 분할)와 불확실 카드 최대 6회, 이미지당 최대 8회를 허용한다. [OCR.space 공식 API 요금표](https://ocr.space/ocrapi)의 무료 한도는 월 25,000회이므로 최악의 8회가 지속되면 다른 OCR 호출을 제외해도 월 3,125장이다. 실제 총 사용량은 다른 형식의 호출까지 합산해야 한다.
- 각 이미지에서 실제 호출 수와 각 응답 지연을 기록하고, P50/P95·최악값 및 무료 한도 소진 추정치를 운영 전 검증한다. 현재 Render 요청 제한 안에서 최악의 선택 재OCR이 완료되는지 확인되지 않았다. 8회 직렬 호출을 그대로 운영 경로에 붙이지 않는다.
- 불확실 카드가 6개를 넘으면 추가 호출 없이 Fail-Closed 한다. 로컬 Tesseract 폴백과 호출 예산은 별도 통합 PR에서 실제 처리시간을 측정해 결정한다. 폴백이 검증 없이 부분 데이터를 저장해서는 안 된다.

## 주소 판단의 범위

카드 시간 범위 안의 두 주소 후보만 사용하며, 안내/결제 제어 문구를 제외하고 행정구역·도로·역·시설명 같은 위치 단서를 요구한다. 대구 밖 목적지도 허용한다. OCR이 주소의 위치 단서를 지웠거나 장소명이 이 목록에 없는 경우 선택 재OCR을 시도하고, 끝내 두 후보가 유일하지 않으면 Fail-Closed 한다. 이 규칙은 실제 장거리/시설명 샘플로 회귀검증하기 전까지 운영 기준으로 확정하지 않는다.

## 실측 및 남은 관문

2026-09-29 Render PR 프리뷰에서 Golden 원본의 OCR.space Engine2 `isOverlayRequired=true`를 실측했다. 처음에는 `22 : 32`형 공백으로 시간 정규식이 실패해 안전 중단됐고, 보정 후 10카드·70,400원·직접결제 1건을 2회 호출로 검증했다. 동일 source_id의 운영 `raw_calls` 저장행과 시각·주소·요금·직접결제 표시가 10/10 일치했다. 운영 경로의 직접결제는 `결제수단`이 아니라 `비고`에 기록된다. 이는 과거 운영 저장 결과와의 대조이며, 동일 OCR 원문으로 두 파서를 동시에 실행하는 shadow 비교는 아니다.

CASSANDRA가 네 쟁점과 이 실측을 독립 검토한 뒤, 통합 PR에서 날짜 추출, 같은 입력의 읽기 전용 shadow, 재OCR 8회 경로의 전체 지연·호출량을 검증한다. 본 PR은 Draft로 유지한다.
